## 1. The big picture

CertDrop is a **monorepo**: one repository holding three packages that depend on each other.

| Package           | What it is                                                                                                                                       | Runs where                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `apps/web`        | The website people use: the four-step wizard and the public verification page                                                                    | In the visitor's browser (hosted on Vercel)                |
| `apps/api`        | Two programs built from one codebase. The **API** answers the website's requests; the **worker** renders PDFs and sends emails in the background | On a server (Render): one process on the free plan, or two |
| `packages/shared` | Rules and data shapes both sides must agree on (validation, the name-fitting algorithm, font data)                                               | Bundled into both                                          |

### How a request travels

1. The organizer opens the website. The browser loads `apps/web`.
2. Each action calls the API at `/api/...`. In production Vercel forwards these to Render; locally
   Vite's dev server does the same. The API checks the input against the shared Zod schemas, reads
   or writes Postgres through Prisma, and replies with JSON.
3. Heavy work isn't done during the request. When a batch is created, the API stores one **job**
   per certificate in Postgres (the pg-boss queue).
4. The **worker** picks up jobs. For each certificate it draws the name onto the template,
   stores the PDF in object storage (R2, or RustFS locally), then emails it.
5. The website polls the API every 2 seconds to show progress.
6. A recipient scans the QR code, which opens `/verify/CD-…` on the website. That page asks the
   API whether the certificate is genuine.

### Words used throughout

- **Template:** the certificate design the organizer uploads (PNG, JPG or PDF).
- **Layout:** where the name and QR code go on the template, plus font, size, colour and alignment.
  Positions are stored as fractions of the page (0 to 1), so they don't depend on screen size.
- **Batch:** one sending run: one template, one layout, one event, many recipients.
- **Certificate:** one recipient's row in a batch. Public ID like `CD-7kQm2xPd9T`.
- **Organizer:** the person using the app, identified only by a verified email address.

## 2. Root of the repository

### Workspace and tooling

**`package.json`**

- **Why:** Every Node project has one. At the root it defines the commands that act on the whole
  monorepo and the tools shared by all packages.
- **What:** Scripts:
  - `dev` starts web, API and worker together with `concurrently`.
  - `bootstrap` starts Docker services, runs migrations and creates the storage bucket.
  - `lint`, `format`, `typecheck`, `test`, `test:e2e`, `build` and `seed:template`.
  - Dev dependencies are shared tools: ESLint, Prettier, TypeScript, Playwright.
  - `packageManager` pins the exact pnpm version.

**`pnpm-workspace.yaml`**

- **Why:** Tells pnpm this is a monorepo and where its packages live.
- **What:** Lists `apps/*` and `packages/*`. `onlyBuiltDependencies` allows install scripts only
  for the few packages that need them (Prisma, esbuild), because pnpm 10 blocks install scripts by
  default for security.

**`pnpm-lock.yaml`**

- **Why:** Records the exact version of every installed package, so every machine and CI installs
  the same thing.
- **What:** Generated by pnpm; never edited by hand. CI installs with `--frozen-lockfile`, which
  fails if it's out of date.

**`tsconfig.base.json`**

- **Why:** One place for TypeScript's strictness settings, so every package is equally strict.
- **What:** `strict` mode, `noUncheckedIndexedAccess` (array access might be `undefined`),
  `verbatimModuleSyntax`, modern ES target. `noEmit`: TypeScript only checks types; bundlers
  produce the JavaScript.

**`tsconfig.json`**

- **Why:** The Playwright config sits at the root, and TypeScript and ESLint need a project that
  includes it.
- **What:** Extends the base settings, adds Node types, and includes only `playwright.config.ts`.

**`eslint.config.js`**

- **Why:** Catches bugs and inconsistent code automatically, in the editor and in CI.
- **What:**
  - Type-aware rules from `typescript-eslint`, such as forbidding `any` and requiring
    `import type` for type-only imports.
  - Node globals for server code and browser globals for the website.
  - React Hooks rules, including the React Compiler checks, for the website.
  - `eslint-config-prettier` last, so ESLint doesn't argue with the formatter.

**`.prettierrc.json`**

- **Why:** Consistent formatting without debates.
- **What:** Single quotes, trailing commas, 110-character lines.

**`.prettierignore`**

- **Why:** Some files shouldn't be reformatted.
- **What:** Skips build output, coverage, the lockfile, the local email outbox, Playwright reports
  and generated SQL migrations.

**`.editorconfig`**

- **Why:** Makes any editor use the same basics before Prettier runs.
- **What:** UTF-8, LF line endings, two-space indentation, final newline.

**`.gitattributes`**

- **Why:** Windows and macOS handle line endings differently; this keeps the repository
  consistent, and keeps Git from corrupting binary files.
- **What:** Text files are stored with LF endings. Images, PDFs and fonts are marked binary.

**`.gitignore`**

- **Why:** Keeps secrets and generated files out of Git.
- **What:** Ignores `node_modules`, build output, every `.env` except the `.env.example` files, the
  local email outbox and test reports.

### Running and shipping

**`docker-compose.yml`**

- **Why:** The app needs Postgres and S3-compatible storage. This starts both locally with one
  command.
- **What:**
  - Postgres 17, with a health check so `docker compose up --wait` waits until it accepts
    connections.
  - RustFS 1.0.3 as the storage server. It stands in for MinIO, which stopped publishing images.
  - Named volumes keep data between restarts.

**`Dockerfile`**

- **Why:** The API and worker run in production as a container image.
- **What:** Two stages.
  - **Build stage:** installs dependencies, bundles the API with tsup, then uses
    `pnpm deploy --prod` to copy only runtime dependencies. It also copies the compiled code,
    Prisma schema and fonts, and generates the Prisma client.
  - **Runtime stage:** a slim Node 24 image with OpenSSL (Prisma needs it), run as the
    unprivileged `node` user, with `FONTS_DIR=/app/fonts`.
  - It also copies `docker-start.sh`, which Render's free plan uses as the start command.
  - The default command starts the API; `node dist/worker.js` starts a separate worker.

**`.dockerignore`**

- **Why:** Keeps the Docker build fast and keeps secrets out of the image.
- **What:** Excludes `node_modules`, build output, `.env` files, `.git` and test output.

**`render.yaml`**

- **Why:** A Render "Blueprint": describes the production servers as code, so deploying is a few
  clicks rather than manual setup.
- **What:** One free web service, `certdrop-api`, set up for the free plan's limits:
  - Render's free plan has no background workers, so `RUN_WORKER_IN_API=true` runs the worker
    inside the API process, rendering one certificate at a time.
  - It has no pre-deploy step, so the start command `sh docker-start.sh` applies database
    migrations first.
  - It blocks outgoing SMTP, so email goes through the Gmail API over HTTPS
    (`EMAIL_PROVIDER=gmail`), one per second, with at most 3 batches per organizer a day to stay
    under Gmail's daily limit.
  - A health check at `/api/health`.
  - Secrets are marked to be entered in the dashboard; the session and OTP secrets are generated by
    Render. The README explains how to split the worker out on a paid plan.

**`playwright.config.ts`**

- **Why:** Configures the end-to-end browser test.
- **What:**
  - Uses Chromium, with traces and screenshots kept on failure.
  - Starts `pnpm dev` automatically, or reuses a running one.
  - `E2E_BASE_URL` points the test at a production preview instead.

**`.github/workflows/ci.yml`**

- **Why:** Every pull request is checked automatically, so broken code can't slip in.
- **What:** Three jobs.
  1. **check:** lint, format check, typecheck, all unit and integration tests, and both builds,
     with Postgres and RustFS running as service containers.
  2. **e2e:** the same services plus migrations and bucket setup, then the Playwright test against
     the full stack. Uploads the report if it fails.
  3. **docker:** checks that the production image builds.

### Documentation

**`README.md`**

- **Why:** The front page of the project.
- **What:** Features, architecture diagrams, local setup, every environment variable, how testing
  works, step-by-step deployment, design decisions and trade-offs, security notes and known
  limitations.

**`docs/CODEBASE.md`**

- **Why:** This file: a guide to every file.

## 3. packages/shared: code used by both browser and server

**Why this package exists:** some rules must be identical on both sides. If the browser and the
server each had their own copy of "what is a valid email" or "how big should this name be", they
would drift apart, and the preview would stop matching the real certificate. Here they're written
once.

The package ships TypeScript source directly: no build step. Vite (website), tsx (development)
and tsup (production server build) all read it as is.

### Package files

**`packages/shared/package.json`**

- **Why:** Declares the package `@certdrop/shared` so the other packages can import it.
- **What:** `exports` points to `src/index.ts`, plus `./fonts/*` so the website can import the font
  files. Its only runtime dependency is `zod`; the tests use `vitest`.

**`packages/shared/tsconfig.json`**

- **Why:** TypeScript settings for this package.
- **What:** Extends the root base and checks `src`.

**`packages/shared/src/index.ts`**

- **Why:** A single entry point, so other code can write `import { … } from '@certdrop/shared'`.
- **What:** Re-exports every module below.

### Data shapes and rules

**`src/auth.ts`**

- **Why:** The sign-in rules both sides enforce.
- **What:**
  - `OTP_POLICY`: 6 digits, a 10-minute lifetime, a 60-second resend cooldown, 5 attempts and 5
    codes per hour.
  - `EmailSchema`: trims and lowercases, then validates.
  - Zod schemas for the request and verify bodies, and for the session response.

**`src/batch.ts`**

- **Why:** The shape of a batch, from the event form to the progress table.
- **What:**
  - Default email subject and message, and `fillPlaceholders` for `{name}`, `{event}` and
    `{issuer}`.
  - `EventDetailsSchema`: event name, issuer, date, subject and message.
  - `BatchCreateSchema`: the body of `POST /batches`, with at most 1,000 recipients.
  - Schemas for batch status and counts, certificate rows (including revoked and delivery
    status), and paginated row queries.

**`src/certificate.ts`**

- **Why:** Defines what a certificate ID looks like and the verify response.
- **What:**
  - The alphabet for IDs: 55 characters, without look-alikes such as 0/O and 1/l/I.
  - `CertIdSchema` validates `CD-` plus 10 characters.
  - `verifyUrl` builds the public link.
  - `VerifyResponseSchema` is either "valid" (with the name) or "revoked" (without it).

**`src/csv.ts`**

- **Why:** The participant-list rules. The browser uses them for instant feedback and the server
  repeats them before sending.
- **What:**
  - `detectColumns` finds the name and email columns from headers like "Full Name" or "E-mail
    Address", including first and last name pairs.
  - `sanitizeCell` strips spreadsheet-formula characters (`= + - @`) so a cell can't run a formula
    if the data is opened in Excel later.
  - `validateRows` produces each row's name and email plus a list of issues: empty, too long or
    unprintable names; missing, invalid or duplicate emails. It also applies the organizer's inline
    fixes.
  - `BATCH_MAX_ROWS = 1000`.

**`src/enums.ts`**

- **Why:** The status words (QUEUED, SENT, …) as plain TypeScript, so the website never has to
  import the database library.
- **What:** Lists of certificate, batch, failed-stage and delivery statuses, with their types. A
  server test checks they match the database enums.

**`src/errors.ts`**

- **Why:** Every API error has the same shape, so the website handles errors in one place.
- **What:** `ApiErrorSchema`: `{ error: { code, message, fields?, retryAfterSeconds? } }`.

**`src/health.ts`**

- **Why:** The shape of `GET /api/health`.
- **What:** Overall status, version, uptime, and database and storage checks.

**`src/layout.ts`**

- **Why:** Defines a layout and rejects impossible ones.
- **What:**
  - `CERT_FONTS` lists the five font IDs.
  - `BoxSchema`: a rectangle as fractions of the page, which must lie on the page.
  - `LayoutSchema`: name box, font, size (8–200 pt), colour (`#rrggbb`), alignment and an
    optional QR box.

**`src/template.ts`**

- **Why:** Template upload rules and file-type detection.
- **What:**
  - Accepts PNG, JPG and PDF up to 10 MB.
  - `IMAGE_TEMPLATE_LONG_SIDE_PT = 842`: images are placed on an A4-length page, so font sizes
    mean the same thing whatever the image resolution.
  - `sniffTemplateType` identifies a file by its first bytes, not its name.
  - Schemas for the upload and complete responses.

**`src/text.ts`**

- **Why:** Name cleaning and "can we print this?" checks.
- **What:**
  - `normalizeName` merges accent characters (Unicode NFC), collapses spaces and trims.
  - `SUPPORTED_RANGES` covers Latin, Greek and Cyrillic.
  - `findUnsupportedCharacters` lists characters outside them, such as Arabic, Devanagari or
    emoji, so those rows are flagged instead of printing wrongly.

### Fonts and the name-fitting algorithm

**`src/fit.ts`**

- **Why:** The heart of "the preview matches the certificate". It decides the font size and line
  breaks for a name in a box.
- **What:**
  - `fitName` uses the chosen size if the name fits, otherwise shrinks it to at most 60% of that
    (`minFontSize`). If it still doesn't fit, it splits onto two balanced lines
    (`balancedSplit`). As a last resort it takes the larger result and flags it.
  - `positionLines` centres the text vertically and works out each line's x position for
    left, centre or right alignment, and its baseline from the font's ascent and descent.
  - Measurement is passed in as a function: canvas in the browser, pdf-lib on the server.

**`src/fonts.ts`**

- **Why:** The list of certificate fonts with what both sides need to know.
- **What:** For each font: its display name, category (serif, script or sans), TTF file name, and
  vertical metrics copied from the file. The fallback font is Noto Sans.

**`src/fontCoverage.ts`**

- **Why:** Browsers can't tell which characters a font has. This table tells them, so the preview
  and the PDF make the same fallback choices.
- **What:** A generated list, per font, of code-point ranges it has no glyph for. Created by
  `apps/api/scripts/font-coverage.ts`; a test fails if it drifts from the font files.

**`src/runs.ts`**

- **Why:** Decides which words use the chosen font and which use the fallback.
- **What:**
  - `fontHasGlyph` checks the coverage table with a binary search.
  - `splitFontRuns` splits a name into runs. If any letter of a word is missing, the whole word
    uses Noto Sans, so typefaces never mix inside a word.

**`packages/shared/fonts/*.ttf`**: `PlayfairDisplay-SemiBold.ttf`, `EBGaramond-Medium.ttf`,
`GreatVibes-Regular.ttf`, `Inter-SemiBold.ttf`, `Montserrat-SemiBold.ttf`,
`NotoSans-SemiBold.ttf`

- **Why:** The real font files. The browser preview and the PDF renderer load the same files, so
  text measures identically.
- **What:** Static TrueType fonts from Google Fonts. The first five are the choices offered;
  Noto Sans is the fallback.

**`packages/shared/fonts/licenses/*-OFL.txt`**: `playfairdisplay-OFL.txt`,
`ebgaramond-OFL.txt`, `greatvibes-OFL.txt`, `inter-OFL.txt`, `montserrat-OFL.txt`,
`notosans-OFL.txt`

- **Why:** The SIL Open Font License allows bundling these fonts on condition that the license
  travels with them.
- **What:** Each font's license text.

### Tests in this package

All run with Vitest (`pnpm test`).

| File                 | What it checks                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `src/auth.test.ts`   | Emails are normalized, bad ones rejected; codes must be exactly 6 digits                                                                 |
| `src/csv.test.ts`    | Column detection across many header styles, first/last pairing, formula stripping, every validation issue, inline fixes, placeholders    |
| `src/fit.test.ts`    | Names keep their size, shrink, wrap to two balanced lines, get flagged, respect box height, never overflow, and are positioned correctly |
| `src/layout.test.ts` | Boxes must lie on the page; unknown fonts and bad colours are rejected                                                                   |
| `src/runs.test.ts`   | Whole words fall back together, consecutive fallback words merge, and Playfair's lone π is handled                                       |
| `src/text.test.ts`   | Name normalization, supported vs unsupported scripts and emoji, and file-type sniffing                                                   |

## 4. apps/api: the server and the background worker

**Why one package for two programs:** the API and the worker share almost everything (database
access, storage, email, configuration). They're two entry points (`server.ts`, `worker.ts`) in
one codebase, built into one Docker image.

### Package files

**`apps/api/package.json`**

- **Why:** Declares the server's dependencies and commands.
- **What:**
  - Scripts:
    - `dev:api` and `dev:worker` use tsx with automatic reload.
    - `build` (tsup) and `start:*`.
    - Database: `db:migrate`, `db:migrate:deploy`, `db:studio`.
    - Maintenance: `storage:init`, `cleanup`, `fonts:coverage`, `seed:template`.
    - `postinstall` regenerates the Prisma client.
  - Runtime dependencies: Fastify and its plugins, Prisma, pg-boss, pino, the AWS S3 SDK, pdf-lib
    with fontkit, qrcode, archiver (ZIP), nanoid, jose (JWT) and zod.
  - `@certdrop/shared` is a dev dependency because the build copies it in.

**`apps/api/tsconfig.json`**

- **Why:** TypeScript settings for the server.
- **What:** Node types, and checks `src`, `test`, `scripts` and the config files.

**`apps/api/tsup.config.ts`**

- **Why:** Production needs plain JavaScript. tsup (built on esbuild) bundles each entry point into
  one file.
- **What:** Builds `server.ts` and `worker.ts` as ES modules for Node 22+, with source maps.
  `noExternal: ['@certdrop/shared']` copies the shared TypeScript into the bundle, while real npm
  packages stay in `node_modules`.

**`apps/api/vitest.config.ts`**

- **Why:** Configures the test runner.
- **What:** Two test projects:
  - `unit`: no external services needed.
  - `integration`: real Postgres and RustFS. Global setups create the test database and bucket,
    and files run one at a time because they share a database.

**`apps/api/.env.example`**

- **Why:** Documents every setting the server needs, with working local values. Copy it to `.env`
  to start.
- **What:**
  - Database and storage settings for the Docker services.
  - Development-only secrets.
  - The file email provider, with commented-out Gmail and Resend settings.
  - `RUN_WORKER_IN_API=false`, because `pnpm dev` runs the worker separately.
  - Cloudflare's public always-pass Turnstile test key.
  - Quotas and retention.
  - `CORS_ORIGINS` for the local preview server.

### Database

**`prisma/schema.prisma`**

- **Why:** The single definition of the database: tables, columns, relations and indexes. Prisma
  generates both the SQL and a typed client from it.
- **What:** Five models.
  - `Organizer`: email and verification time.
  - `OtpCode`: hashed code, expiry, attempts, used time.
  - `Template`: storage key, type, size, page size, status `PENDING` then `READY`, deletion time.
  - `Batch`: event details, email text, layout as JSON, status, the time files were deleted.
  - `Certificate`: public ID, row number, name, email, PDF key, status, failed stage, error,
    attempts, provider message ID, delivery status, sent and revoked times.
  - Enums mirror the status words in `packages/shared/src/enums.ts`.
  - Indexes support the common queries: codes for an email in the last hour, counts per batch
    and status, daily quotas.

**`prisma/migrations/20261020062543_init/migration.sql`**

- **Why:** The SQL that creates the schema. Migrations make database changes repeatable and
  reviewable.
- **What:** Generated by `prisma migrate dev`: the `CREATE TYPE`, `CREATE TABLE`, index and
  foreign-key statements. Applied with `prisma migrate deploy` (in `pnpm bootstrap`, CI and
  `docker-start.sh` on Render).

**`prisma/migrations/migration_lock.toml`**

- **Why:** Prisma records which database the migrations were written for.
- **What:** `provider = "postgresql"`. Generated; don't edit.

### Entry points

**`src/server.ts`**

- **Why:** The API process's starting point.
- **What:**
  - Loads and validates config.
  - Creates the logger, database client, storage client and email provider.
  - Starts pg-boss and makes sure the queues exist. Normally in "enqueue only" mode; with
    `RUN_WORKER_IN_API` it runs as a full worker too, and starts the job runner (see
    `jobs/runner.ts`) in this process.
  - Builds the app with the real Turnstile verifier if a secret is set, then listens on `PORT`.
  - Shuts down cleanly on `SIGINT`/`SIGTERM`, finishing in-flight jobs when it runs the worker.

**`src/worker.ts`**

- **Why:** The separate background process's starting point. It's separate so slow PDF and email
  work never delays web requests, and each part can be scaled or restarted on its own. Not used
  on Render's free plan, where the API runs the worker itself.
- **What:**
  - Starts pg-boss as a full worker and hands it to the job runner.
  - Logs and survives unhandled promise rejections; exits on truly unexpected crashes so the
    platform restarts it.
  - Finishes in-flight jobs before stopping.

**`docker-start.sh`**

- **Why:** Render's free plan has no "run before deploy" step, so migrations must run when the
  container starts.
- **What:** Runs `prisma migrate deploy` (which takes a lock, so overlapping starts are safe),
  then replaces itself with the API process.

**`src/app.ts`**

- **Why:** Builds the HTTP application from dependencies passed in (database, storage, email,
  queue, captcha, clock), rather than creating them itself. Tests can then pass fakes.
- **What:**
  - Creates Fastify with a 1 MB body limit and the trusted-proxy setting.
  - Removes the `text/plain` body parser, so only JSON is accepted.
  - Registers security headers (helmet), CORS (allowlist), cookie parsing and rate limiting (off
    unless a route opts in).
  - Registers the error handlers, then every route group under `/api`.

### Configuration and shared helpers (`src/config`, `src/lib`)

**`src/config/env.ts`**

- **Why:** The app should refuse to start with bad configuration, not fail later in a confusing
  way.
- **What:**
  - A Zod schema for every environment variable, with types, defaults and limits.
  - Cross-checks:
    - Resend needs an API key; Gmail needs its client ID, client secret and refresh token.
    - Production refuses the file email provider.
    - Production requires Turnstile.
  - `loadEnv` reports problems by variable name and never prints values, which may be secrets.

**`src/lib/async.ts`**

- **Why:** A database or storage call that hangs shouldn't hang a request.
- **What:** `withTimeout` rejects if a promise takes longer than a set time. The health check
  uses it.

**`src/lib/captcha.ts`**

- **Why:** Proves a human requested a sign-in code, so bots can't use CertDrop to email
  strangers.
- **What:**
  - `CaptchaVerifier` interface.
  - `TurnstileVerifier` asks Cloudflare whether a token is valid. If Cloudflare is unreachable it
    raises `CaptchaUnavailableError`, and the route fails closed.
  - `disabledCaptcha` for local development and tests.

**`src/lib/certId.ts`**

- **Why:** Generates public certificate IDs.
- **What:** `generateCertId()` returns `CD-` plus 10 characters from the shared alphabet, using
  nanoid's cryptographically secure random generator.

**`src/lib/errors.ts`**

- **Why:** One consistent error format for the website, and no internal details leaked.
- **What:**
  - `HttpError` for expected failures, with an optional retry-after time.
  - `registerErrorHandlers` turns `HttpError`, Zod validation errors (with per-field messages) and
    Fastify's own 4xx errors into the shared JSON shape. Anything unexpected becomes a logged 500
    with a generic message.
  - Unknown routes return a JSON 404.

**`src/lib/logger.ts`**

- **Why:** Structured logs that never leak personal data.
- **What:**
  - `createLogger` uses pino: readable output in development, JSON elsewhere.
  - Redaction removes cookies, authorization headers, emails, codes and tokens from log fields.
  - `maskEmail` turns `jane@example.com` into `ja***@example.com` for logs.

**`src/lib/prisma.ts`**

- **Why:** One place that creates the database client.
- **What:** `createPrisma` passes the validated `DATABASE_URL` to `PrismaClient`.

**`src/lib/quota.ts`**

- **Why:** Daily caps per organizer.
- **What:** `quotaWindowStart` returns "24 hours ago". `enforceDailyQuota` throws a friendly 429 when
  the cap is reached.

**`src/lib/rateLimiter.ts`**

- **Why:** Email providers limit how many emails you send per second. Pacing sends avoids errors
  instead of hitting the limit and retrying.
- **What:** `IntervalRateLimiter.acquire()` waits until the next free slot. Slots are reserved
  immediately, so concurrent senders queue up fairly.

**`src/lib/storage.ts`**

- **Why:** All file storage goes through one small interface, so R2, RustFS or a test fake can sit
  behind it.
- **What:** The `Storage` interface and `S3Storage`, built on AWS SDK v3.
  - `ping`, `head`, `getBytes`, `getStream`, `putBytes`, `delete` and `deleteMany` (1,000 keys per
    request).
  - `presignPut`: an upload URL bound to the exact size and type.
  - `presignGet`: a download URL with a readable file name.
  - `ensureBucket`: creates the bucket and sets its CORS rules.
  - `contentDisposition` builds safe download headers for names like "Zoë".
  - The client uses "checksums only when required", so presigned uploads work with R2 and RustFS.

**`src/lib/webhookSignature.ts`**

- **Why:** Anyone could post fake "email delivered" events to the webhook URL. This proves a
  message really came from Resend.
- **What:**
  - `verifySvixSignature` recomputes the HMAC-SHA256 over the message ID, timestamp and exact
    body, compares it in constant time, rejects messages older than 5 minutes, and accepts any of
    several signatures (for key rotation).
  - `signSvix` creates signatures for tests.

### Features (`src/modules`)

Each folder is one feature: its routes, plus its logic when there's enough to separate.

**`src/modules/health/health.routes.ts`**

- **Why:** Hosting platforms and monitoring need a "are you alive and connected?" endpoint.
- **What:** `GET /api/health` checks the database (`SELECT 1`) and storage (bucket reachable), each
  with a 2-second timeout. Returns 200 when both are OK, 503 otherwise.

**`src/modules/auth/auth.routes.ts`**

- **Why:** The sign-in endpoints.
- **What:**
  - `POST /auth/otp/request`: checks Turnstile, then asks the OTP service to send a code. Limited
    to 10 per IP per 15 minutes.
  - `POST /auth/otp/verify`: checks the code and sets the session cookie. Limited to 30 per 15
    minutes.
  - `GET /auth/me` returns the current organizer or `null`. `POST /auth/logout` clears the cookie.
  - Responses are marked `no-store` so they're never cached.

**`src/modules/auth/otp.service.ts`**

- **Why:** The one-time code logic, kept apart from HTTP so it's easy to test and reason about.
- **What:**
  - `request(email)`:
    - Enforces a 60-second cooldown (reporting the exact remaining wait) and 5 codes per hour.
    - Generates a random 6-digit code and stores only its HMAC, bound to the email.
    - Cancels older codes, then emails the code. If sending fails, the code is deleted so you can
      retry immediately.
  - `verify(email, code)`:
    - Finds the newest live code and counts the attempt _before_ comparing, atomically, so
      parallel guesses can't exceed 5.
    - Compares in constant time and marks the code used.
    - Creates or updates the organizer.

**`src/modules/auth/session.ts`**

- **Why:** Remembers who's signed in without a sessions table.
- **What:** `SessionManager`:
  - `issue` signs a 2-hour JWT (jose, HS256) and sets it as an `HttpOnly`, `SameSite=Strict`,
    `Path=/api` cookie, `Secure` in production.
  - `read` verifies the token and returns the organizer, or `null` if it's missing, expired or
    tampered with.
  - `clear` removes the cookie.

**`src/modules/auth/guard.ts`**

- **Why:** Most routes are for signed-in organizers only.
- **What:**
  - `requireOrganizer` is a pre-handler that reads the session or answers 401, and attaches the
    organizer to the request.
  - `currentOrganizer(request)` gets it back with the right type.

**`src/modules/templates/templates.routes.ts`**

- **Why:** Template upload without sending large files through the API.
- **What:**
  - `POST /uploads/template` checks type, size and the daily cap, creates a `PENDING` row, and
    returns a presigned upload URL valid for 5 minutes.
  - `POST /uploads/template/:id/complete`:
    - Only works on your own template.
    - Checks the stored file's size, then inspects it.
    - Marks it `READY` with its page size, or deletes the file and row and answers 422 with the
      reason.
    - Safe to call twice.

**`src/modules/templates/inspect.ts`**

- **Why:** The browser's claim about a file can't be trusted, so the server checks the real bytes.
- **What:**
  - `inspectTemplate` confirms the type from the first bytes and that it matches what was
    declared.
  - **PNG:** reads the size from the header, then checks it's at most 40 megapixels (_before_
    decoding, against "decompression bombs") and at least 600px. A trial decode catches damage.
  - **JPEG:** walks the file to find its size and EXIF rotation, and rejects rotated photos
    (browsers and pdf-lib disagree on them).
  - **PDF:** loads it and rejects encrypted, multi-page, rotated or malformed files, then reads
    the visible page size.
  - Images are given an A4-length page size in points.

**`src/modules/batches/batches.routes.ts`**

- **Why:** Creating and following a batch: the main job of the app.
- **What:**
  - `POST /batches`:
    - Checks the daily cap and that the template is yours and ready.
    - Re-validates every row with the shared rules and generates certificate IDs.
    - In **one database transaction**, creates the batch, the certificate rows and the generate
      jobs, so you never get a batch without jobs.
  - `GET /batches/:id` returns status and counts, calculated from the rows.
  - `GET /batches/:id/certificates` returns rows in pages, filterable by status, using the row
    number as the cursor.
  - `POST /batches/:id/retry-failed` puts failed rows back at the stage that failed.
  - `POST …/revoke` and `…/restore` mark a certificate withdrawn, or undo it.
  - `GET …/certificates/:certId/download` redirects to a 5-minute signed link.
  - `GET /batches/:id/zip` streams a ZIP, fetching one PDF at a time so memory stays flat.
  - Every route checks ownership; someone else's batch looks exactly like a missing one.
  - After the retention cleanup, downloads answer 410 Gone.

**`src/modules/verify/verify.routes.ts`**

- **Why:** The public check behind QR codes and email links.
- **What:** `GET /verify/:certId`:
  - Rejects malformed IDs and answers only for issued certificates (generated or sent).
  - Returns "valid" with name, event, issuer and date, or "revoked" without the name.
  - Never returns the email address.
  - Limited to 60 per minute per IP, cached for 60 seconds, and marked `noindex` so names don't
    appear in search engines.

**`src/modules/webhooks/resend.routes.ts`**

- **Why:** Resend reports what happened to each email (delivered, bounced, marked as spam).
- **What:** `POST /webhooks/resend`:
  - Keeps the raw request body, because the signature covers the exact bytes, and verifies it.
  - Maps the event to a delivery status and updates the certificate with that provider message ID.
  - The status only moves forward (delivered → bounced → complained), since events can arrive out
    of order.
  - Returns 404 if no secret is configured.

### Background jobs (`src/jobs`)

**`src/jobs/boss.ts`**

- **Why:** Creates the pg-boss job queue client.
- **What:** `createBoss` connects to Postgres and logs pg-boss errors and warnings. For the API it
  turns off maintenance and cron, since only the worker runs those.

**`src/jobs/queues.ts`**

- **Why:** Queue names, retry policies, and a small interface the rest of the code uses instead of
  pg-boss directly.
- **What:**
  - Two queues:
    - `certificate-generate`: 3 retries with backoff.
    - `certificate-send`: 5 retries, starting at 20 seconds and capped at 10 minutes.
  - `ensureQueues` creates them if missing.
  - `PgBossCertificateQueue` inserts jobs, optionally inside an existing database transaction.
    Each job gets a singleton key so it can't be queued twice.

**`src/jobs/certificates.ts`**

- **Why:** The work itself: turning rows into PDFs and emails.
- **What:** `CertificateProcessor`.
  - `generate`:
    - Loads the row; does nothing if it isn't `QUEUED`, which makes duplicate jobs harmless.
    - Turns the template into a base PDF once per template (cached, at most 20 kept).
    - Renders the certificate and stores the PDF.
    - In one transaction, moves the row to `GENERATED` and queues the send job.
  - `send`:
    - Waits for the rate limiter, then emails the PDF with an idempotency key.
    - Moves the row to `SENT` with the provider's message ID.
  - Errors:
    - Retried by pg-boss with backoff.
    - On the last attempt, or for errors retrying can't fix, the row is marked `FAILED` with the
      reason and stage, and the process carries on.
  - `finishIfDone` marks the batch complete when nothing is left pending.
  - `registerCertificateWorkers` connects both methods to their queues with concurrency limits.

**`src/jobs/cleanup.ts`**

- **Why:** Data minimization: files shouldn't be kept forever.
- **What:** `CleanupService.run`:
  - Deletes generated PDFs of batches older than the retention period (default 30 days), and old
    templates.
  - Deletes uploads that were never completed (older than a day) and old one-time codes.
  - Keeps every database record, so verification still works.
  - Runs daily at 03:00 UTC and on every start (scheduled in `runner.ts`), and is safe to repeat.

**`src/jobs/runner.ts`**

- **Why:** The worker's setup, shared by the separate worker process and by the API when it runs
  the worker itself on free hosting.
- **What:** `startJobRunner`:
  - Creates the certificate processor (database, storage, email, fonts, queue, an email rate
    limiter) and registers it on the generate and send queues.
  - Schedules the daily cleanup cron, and also queues a cleanup on start, because a server that
    sleeps when idle is rarely awake at 03:00. Restarts within 6 hours don't queue another one.

### PDF generation (`src/pdf`)

**`src/pdf/render.ts`**

- **Why:** Draws each certificate.
- **What:**
  - `prepareBasePdf` turns the template into a clean one-page PDF: it copies the first page of a
    PDF, or places an image on a page of the right size.
  - `renderCertificate`:
    - Loads the base PDF and embeds the chosen font whole (subsetting corrupted glyphs in
      testing). It adds Noto Sans only if the name needs it.
    - Runs the **same** `fitName` and `positionLines` as the browser, with pdf-lib measurements,
      and draws each word run in its font and colour.
    - Draws the QR code and sets document metadata (title, author, keywords).

**`src/pdf/fonts.ts`**

- **Why:** Reading font files from disk for every certificate would be wasteful.
- **What:** `FontLibrary` loads each TTF once per process from `FONTS_DIR` and caches it; a failed
  read is retried next time.

**`src/pdf/qr.ts`**

- **Why:** The verification QR code.
- **What:** `drawQrCode` generates the QR pattern with medium error correction (survives about
  15% damage). It draws it as vector rectangles with the standard white border, merging adjacent
  dark squares into one rectangle to keep the file small. Vector means it stays sharp at any print
  size.

### Emails (`src/email`)

**`src/email/types.ts`**

- **Why:** The common language of all email providers.
- **What:**
  - `EmailMessage`: to, sender name, reply-to, subject, text, HTML, attachments, idempotency key.
  - `EmailProvider` interface.
  - `EmailSendError`, which says whether retrying could help.
  - `sanitizeDisplayName` strips characters that could inject extra headers from the sender
    name; `formatFrom` builds `"Name" <address>` with it.

**`src/email/index.ts`**

- **Why:** Picks the provider from configuration.
- **What:** `createEmailProvider` returns the Gmail, Resend or file provider. To add SES or SMTP,
  add a class and a case here.

**`src/email/gmail.provider.ts`**

- **Why:** Sends real email without owning a domain, from a Gmail account. It uses Google's web
  API rather than SMTP, because Render's free plan blocks SMTP.
- **What:**
  - Exchanges the stored refresh token for a short-lived access token, caches it until a minute
    before it expires, and lets concurrent sends share one refresh.
  - `buildMimeMessage` writes the raw email: headers (non-English names and subjects encoded with
    `encodeHeader`), text and HTML versions, and the PDF attachment, all in base64.
  - Uploads it to Gmail's `messages.send` media endpoint, which accepts up to 35 MB.
  - Network errors, 429, 5xx and short-term rate limits are retryable; the daily cap and other
    errors are not. A revoked refresh token fails with instructions to create a new one.
  - Gmail has no idempotency key, so a retry after a timeout can deliver twice.

**`src/email/resend.provider.ts`**

- **Why:** Sends real email through Resend, for deployments with a verified domain.
- **What:**
  - Calls Resend's REST API with `fetch`; a whole SDK isn't needed for one endpoint.
  - Sends the attachment as base64 and the idempotency key as a header, with a 15-second timeout.
  - Network errors, 429 and 5xx are marked retryable; other 4xx responses are not.

**`src/email/file.provider.ts`**

- **Why:** Lets you run and test everything locally without sending real email.
- **What:** Writes each email to its own folder under `.mail-outbox`: `message.json` (headers and
  text), `message.html` (open it in a browser) and any attachments. Folder names use a timestamp
  and random ID, never the address.

**`src/email/templates/layout.ts`**

- **Why:** Shared email HTML.
- **What:** `escapeHtml` makes text safe inside HTML. `emailLayout` wraps content in a simple,
  centred, inline-styled card that email clients display reliably.

**`src/email/templates/otp.ts`**

- **Why:** The sign-in code email.
- **What:** `otpEmail` builds the subject ("123456 is your CertDrop code"), plain text and HTML,
  with a footer explaining why the email was sent.

**`src/email/templates/certificate.ts`**

- **Why:** The email each participant receives.
- **What:**
  - `certificateEmail` fills `{name}`, `{event}` and `{issuer}` in the organizer's subject and
    message. It sets the sender name to the issuer and reply-to to the organizer.
  - It adds a "Verify this certificate" button, the certificate ID and a footer naming the issuer
    and event, plus the PDF named via `certificateFileName` ("Certificate - Event - Name.pdf",
    with unsafe characters removed).
  - The idempotency key is the certificate ID.

### Maintenance scripts (`scripts`)

**`scripts/storage-init.ts`**

- **Why:** The bucket and its upload CORS rules must exist before the app works.
- **What:** Creates the bucket if needed and allows uploads from `PUBLIC_APP_URL` and
  `CORS_ORIGINS`, retrying while the storage container starts. Run by `pnpm bootstrap`; also usable
  against R2.

**`scripts/cleanup.ts`**

- **Why:** Run the retention cleanup now instead of waiting for 03:00 UTC.
- **What:** Builds a `CleanupService` from the environment, runs it once and disconnects.

**`scripts/font-coverage.ts`**

- **Why:** Regenerates `packages/shared/src/fontCoverage.ts` when a font changes.
- **What:** For every printable character in the supported ranges, checks each font with fontkit,
  records the missing ones as compact ranges and writes the TypeScript file. Its `computeCoverage`
  function is also used by a test.

**`scripts/gmail-token.ts`**

- **Why:** The Gmail provider needs a refresh token, which Google only gives out after you sign in
  and approve access in a browser. Run once, on your own computer.
- **What:**
  - Starts a temporary local web server and prints a Google sign-in link asking only for
    permission to send email.
  - Uses PKCE and a random `state` value, so an intercepted or forged redirect is useless.
  - Exchanges the returned code for tokens and saves `GMAIL_REFRESH_TOKEN` in `apps/api/.env`
    rather than printing it: a long value copied out of a wrapped terminal line is easily
    damaged. It prints the token's fingerprint, which the server also logs at startup
    (`gmail credentials loaded`), so the deployed value can be checked without revealing it.
  - With an address argument, sends a test email to confirm everything works.

**`scripts/make-sample-template.ts`**

- **Why:** A realistic template for demos and testing, generated from code rather than drawn by
  hand.
- **What:** Draws an A4 landscape certificate with pdf-lib: cream background, gold double border,
  headings, an empty name area with a line under it, and signature lines. Saves it to
  `seed/sample-template.pdf`.

### The wizard (`src/features/wizard`)

**`features/wizard/Wizard.tsx`**

- **Why:** The four-step flow that holds everything together.
- **What:**
  - Wraps the steps in the draft provider and loads steps 2–4 only when needed.
  - Lets you reach a step only when every earlier step is complete. Signing out or replacing the
    CSV with a broken one sends you back to the step that needs attention.
  - Pressing Enter on the page continues.
  - Animates between steps and shows Back and Continue, with a hint explaining why Continue is
    disabled.
  - Locks earlier steps once a batch is sending, and "Start another batch" resets everything.

**`features/wizard/Stepper.tsx`**

- **Why:** The progress indicator at the top of the wizard.
- **What:** Numbered steps (a check once done) that you can click to go back. Only the current
  label shows on phones. Screen readers hear "completed" or "not yet available".

**`features/wizard/steps.tsx`**

- **Why:** One list of the four steps.
- **What:** Each step's ID, label, title, description and icon.

**`features/wizard/useStepStatus.ts`**

- **Why:** Decides whether each step is done, and what to tell the organizer if not.
- **What:** Returns "complete" plus a hint per step, such as "Fix or skip 3 rows" or "Complete the
  event details to continue".

## 7. e2e: the browser test

**`e2e/happy-path.spec.ts`**

- **Why:** The final proof that the whole product works for a real user, in a real browser.
- **What:** Plays one organizer's full journey:
  1. Sign in, with the code read from the email outbox.
  2. Upload the sample template and turn on the QR code.
  3. Upload the sample CSV, skip the 4 bad rows, and fill in the event.
  4. Send 10 certificates and wait for "All sent".
  5. Open a recipient's verify link from their email and see "Valid certificate".
  - Fails if the browser reports any Content-Security-Policy violation, and prints any browser
    error to help debugging.

**`e2e/outbox.ts`**

- **Why:** The test needs to "receive" emails.
- **What:** `waitForEmail(to, since)` watches the local email outbox for the newest email to an
  address, ignoring older runs.

**`e2e/tsconfig.json`**

- **Why:** TypeScript settings for the test.
- **What:** Node types; checks this folder.
